### Docs and copy

**Every sentence true of the shipped code. Luke approves customer copy.**

1. Read the code the page describes. Check each claim against it. When the
   code is wrong rather than the page, route it to Bug fix. If the right
   behaviour is a design change, grill it per Design.
2. Write the change through the review loop. For customer-facing copy,
   show it before you commit. For a rewrite across many pages, show one
   page as a sample first.
3. Follow the repo's `docs/site/README.md`, the `technical-writing` skill,
   and simplified technical English. Simplified technical English sets the
   ceiling (clear, one reading), and the copy should still read easily:
   use contractions and joined sentences where they read more comfortably,
   per `technical-writing`'s "Vary the rhythm" and `unslop` rule 34. Run
   `unslop` over everything you wrote, not only part of it.
4. Leave out instructions a reader at that level already knows.
5. Keep doc links pointing at public repos. A private repo's path 404s for a
   customer.
6. Wrap-up.

**Reply:** the copy or a link to it, and which claims you checked against
which code.
