### Prototype

**A throwaway that settles a question by running it, so it never reaches
Luke as an opinion.**

1. Name the question it settles: which approach is faster, whether a query
   fits its budget, how a layout reads. No question means no prototype.
2. Build the smallest thing that answers it, in the scratchpad or on a
   throwaway branch, never in production source. Skip tests and polish.
3. When you compare options, build each one and run them the same way.
4. Observe the answer: a timing, an output, a screenshot. The observation
   is the result.
5. Act on it. If it settles a call that's yours under the Principles,
   decide it and record it in the ADR with what the prototype showed. If
   the call is still Luke's, put the evidence in the grill round with your
   recommendation.
6. Delete the throwaway, or say where it is. It never lands as it is.
7. Wrap-up.

**Reply:** the question, what you built, what it showed, and what you
decided or now recommend.
