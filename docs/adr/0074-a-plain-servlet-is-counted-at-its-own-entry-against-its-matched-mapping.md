# A plain servlet is counted at its own entry against its matched mapping

Decided on 2026-10-18 in a grill on the servlet module. A plain servlet application reported no endpoints, and ADR 0072 found no marker class that tells it apart from Spring's `DispatcherServlet` or Jersey's `ServletContainer`. The servlet API gives no point where registration is final: the spec says `ServletRegistration.addMapping` throws once a context is initialised, but Tomcat 9 and 11 (`ApplicationServletRegistration.addMapping`, live through `MapperListener`), Jetty (`ServletHandler.addServletWithMapping`) and Undertow 2.3 (`DeploymentImpl.tryAddServletMappings`) all accept a mapping after start, and no portable hook marks a context as started.

- **One `servlet` module for `javax.servlet` and `jakarta.servlet`**, compiled against `javax.servlet-api` 4.0.1 and rebound to `jakarta.servlet` where the woven method takes that namespace, as the Spring MVC module does.
- **Servlet 4.0 is the floor.** A request is counted against `HttpServletRequest.getHttpServletMapping()`, which Tomcat 9, Jetty 10 and Undertow 2.0.42 are the first to implement. On an older servlet API the call fails to link and the module disables itself with `LINKAGE_ERROR`.
- **Counted at the servlet's entry, for a `REQUEST` dispatch only.** A filter that answers first leaves the request uncounted, as it does for the Spring MVC module. A `FORWARD`, `INCLUDE`, `ASYNC` or `ERROR` dispatch counts nothing: a request counts once, and an error page is not a call.
- **Declared at a context's first counted request**, from `getServletRegistrations()`. The module holds the context weakly and reads its registrations again at each flush, so a mapping added late is declared within one flush interval. A context that never receives a request declares nothing, as a Vert.x router does (ADR 0073).
- **Verbs come from the `do*` methods the servlet's class declares** below `HttpServlet`, read from the class file. This is the rule `HttpServlet.doOptions` uses to build `Allow`. `doGet` declares `GET`, and a `HEAD` counts against it unless the class declares `doHead`. `doPost`, `doPut` and `doDelete` declare their verbs. `doPatch` declares `PATCH` only on Servlet 6.1, since `HttpServlet.service` answers `PATCH` with 501 before 6.1. `doOptions` and `doTrace` declare a verb only when the class declares them. A class that overrides `service`, or a servlet that is not an `HttpServlet`, has the verb `*`. A request whose verb the servlet does not declare counts nothing. The handler is the `do*` method, or `service` for a `*` servlet. A `do*` that only calls `super` reads as served, as it does for `doOptions`.
- **Exact and path mappings are path templates**, and the context root `""` is `/`. **An extension mapping (`*.do`) and the default mapping (`/`) are servlet pattern templates**, kept exactly as written under a third `EndpointTemplateKind`, since no path template matches at any depth or matches only what nothing else did. The server accepts the kind before an agent sends it.
- **The context path is left out of the template**, as Spring, WebFlux and JAX-RS leave theirs out. Two applications in one container that map the same pattern merge, by the identity rule.
- **An owned servlet is left out**, whatever its module's state: `DispatcherServlet` and its subclasses (Grails' among them) for Spring MVC; Jersey's `ServletContainer`, RESTEasy's `HttpServletDispatcher` and `HttpServlet30Dispatcher`, and CXF's `CXFServlet` and `CXFNonSpringJaxrsServlet` for JAX-RS; `DefaultMicronautServlet` for Micronaut; Ktor's `ServletApplicationEngine` in both namespaces; Javalin 6 and 7's `JavalinServlet`. A framework servlet no module counts behind, such as Vaadin's, JSF's `FacesServlet`, Spring WS's `MessageDispatcherServlet` or the H2 console, is a plain servlet.
- **The container's own servlets are left out by exact class name**: Tomcat's `DefaultServlet` and `JspServlet` (which serves `<jsp-file>` registrations too), Jetty's `DefaultServlet` in each of its packages, `JettyJspServlet` and `ServletHandler$Default404Servlet`, Undertow's `DefaultServlet`, and Quarkus's `QuarkusErrorServlet`. An adopter's subclass of one is the adopter's code and is counted. A container not on the list has its default servlet counted as a servlet at `/`, which is noise, never absence.
- **A mapping outside the spec's five forms disables the module.** Jetty accepts regex and URI-template path specs as servlet mappings. A registration holding one disables the module with `ROUTE_WALK_FAILED`, and a `REQUEST` dispatch to a declared servlet whose mapping has no match type disables it with `ADVICE_FAILED`.

Proved on Tomcat 9.0, 10.1 and 11, Jetty 10 and 12 (ee10), and Undertow 2.3, with Jetty 9.4 showing the `LINKAGE_ERROR` floor and a Spring Boot embedded Tomcat showing `dispatcherServlet` left out, the H2 console counted, and no request counted by two modules.

## Considered options

- **Counting where the container matches the mapping, before the filters.** Rejected: it needs version-sensitive internal hooks in Tomcat's `Mapper`, Jetty's `ServletHandler` and Undertow's `ServletPathMatches`, against one portable hook with the Spring module's semantics.
- **Declaring from per-container "started" hooks** (`StandardContext.startInternal`, `ServletHandler.initialize`, `DeploymentManagerImpl.deploy`). Rejected: three internal hooks that still miss a mapping added after start.
- **`*` for every mapping**, as the JDK `HttpServer` module does. Rejected: a verb nobody sends to a live mapping could never show as never called.
- **Counting a single-mapping servlet on a container older than Servlet 4.0**, or re-running the spec's path matching. Rejected: the first counts part of an application, which is worse than a disabled module, and the second guesses at container matching rules.
- **Counting an owned servlet while its module is off.** Rejected: a Spring application would report one `* /` endpoint taking every hit, hiding the disabled module behind a busy endpoint.
- **Counting `CXFServlet` as a servlet.** Rejected: its JAX-RS requests would count under two identities. Its SOAP traffic goes uncounted and is listed as not covered.
- **Extension and default mappings as regex templates, squeezed into the path grammar, or left out.** Rejected: `*.do` is not a regular expression, `/*` would merge the default mapping with a real `/*` mapping, and leaving them out hides servlets that serve.
- **Counting JSP pages.** Deferred: each page runs inside the container's one JSP servlet, so counting a page needs a hook in the JSP engine.

## Amended on 2026-10-18: what building it on Tomcat showed

- **Tomcat 9.0.123 and 10.1.61 refuse a late `addMapping`.** `ApplicationServletRegistration.addMapping` throws `IllegalStateException` once the context is initialised (message key `applicationServletRegistration.ise`, absent in 9.0.83 and 10.1.46). Tomcat 11.0.24 has no such check. A mapping can still arrive after start through container internals: Tomcat's `Context.addServletMappingDecoded`, Jetty's `ServletHandler.addServletWithMapping`, Undertow's `addMapping`. Such a mapping is counted from the flush after it was added, since only the flush reads registrations again.
- **One hook per request.** The advice is woven onto every public `service(ServletRequest, ServletResponse)` a servlet class declares, `HttpServlet`'s own included, and a servlet's keys are bound only for the most derived class that declares it. A `service` that calls `super.service` passes through several woven frames, and exactly one finds an entry.
- **The container list gains Jetty's `NoJspServlet`**, which Jetty registers as `jsp` when no JSP engine is present, and every Jetty name is matched in the ee11 packages as well as ee8 to ee10.
- **A walk that cannot vouch for a servlet disables the module with `ROUTE_WALK_FAILED`**: a servlet class whose class file cannot be read, a registration with no class name, or any throw while a context's registrations are read. The five-form check applies only to servlets the module counts, so an owned or container servlet with an unusual mapping disables nothing.
