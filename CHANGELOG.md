# Changelog

All notable changes to the agent and the testkit, which share a version, are recorded here in the
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format.

`scripts/release.sh` and the release workflow both require a `## [X.Y.Z]` section with a body for each release.
Keep link reference definitions (`[0.1.0]: https://...`) at the bottom of the file: the first one ends
the section being read.

## [Unreleased]

### Added

- `DeltaBatch` gains `flush_complete` on the wire. The agent sets it on the last delta batch of a flush when every delta batch the flush sent before it was confirmed.
- The route bridge removes the prefix OpenTelemetry added to a route: the context path of the servlet instrumentation, the servlet path of JAX-RS (Jersey, CXF and RESTEasy) and the context path of the Spring MVC library instrumentation. A request the Spring MVC, JAX-RS or `servlet` module counted is no longer counted again as `/shop/orders`. The Spring WebFlux library instrumentation's base path is not removed.
- Endpoint counting for plain servlets, as the module `servlet`, on Tomcat 9.0, Jetty 10 (`javax.servlet`, Servlet 4.0), Tomcat 10.1 and 11, Jetty 12 with `ee10`, Undertow 2.3 and Spring Boot 3 on embedded Tomcat (`jakarta.servlet`, Servlet 6.0 and 6.1). It counts a request at the servlet's own entry, for a `REQUEST` dispatch only, against the mapping the container matched, and declares a context's mappings at the first request the context receives and again before each manifest. The verbs are the `do*` methods the servlet's classes declare below `HttpServlet`, read from the class files, and a `HEAD` counts against `GET` unless the class declares `doHead`. A class that overrides `service`, and a servlet that is no `HttpServlet`, have the verb `*`. An extension mapping (`*.do`), the default mapping (`/`) and an exact mapping the naming rules would change or that holds a star or brace (`/orders/`, `/api*`) are servlet pattern templates, and the context root is `/`. Servlets another module counts behind, and a container's own servlets, are left out. A mapping outside the five forms the servlet specification defines switches the module off with the kind `ROUTE_WALK_FAILED`, and a container that implements a servlet API older than 4.0 with `LINKAGE_ERROR`, whether the application ships the 3.1 or the 4.0 API jar. A servlet that calls another servlet's `service` directly counts once, in the servlet the container matched. Ktor's and Javalin's servlets are left out only where their module covers the release, so a Javalin 5 or Ktor 1 servlet is counted as a plain servlet.
- Framework markers: the agent reports that a framework's own routing loaded, as `framework_markers` on the manifest and in the wire format. Each marker carries its id, the class set that matched and the time of the sweep that saw it, and is delivered once. The loaded-class sweep looks on every flush, from the names of classes already defined, never by loading one. A marker is an observation; the server decides what it means. The first markers are `grpc-server`, `armeria-server`, `undertow-routing-handler`, `javalin-5`, `webflux-router-without-dispatcher`, `play-server`, `helidon-webserver`, `struts2-dispatcher` and `grails-url-mappings`.
- JAX-RS resources under Quarkus REST (RESTEasy Reactive) inherit a class-level `@Path` as Quarkus resolves it, from a direct abstract superclass or an interface: the agent detects Quarkus REST's server classes on the resource class's loader. A class implementing an interface that carries the `@Path`, and a concrete subclass of an abstract `@Path` class, are declared and counted. Quarkus serves the subclass of an abstract class only when it is the only one, so with two or more the agent declares endpoints Quarkus never serves, which read as never called. The INFO line for an ignored supertype `@Path` is logged once per class, for at most 16 classes. A synthetic class, as Quarkus ArC's generated subclasses and client proxies are, is never read as a resource.
- Endpoint counting for Vert.x Web 4.5 to 5.x, as the module `vertx-web`. It declares the routes reachable from a root router at that router's first request, and again after a router it reached changed, and counts a route each time a request matches it, before the handler runs, so a request that passes through several routes counts each. `:name` and `:name::type` read as `{name}`, a mounted sub-router adds its path, and a router mounted in several places declares an endpoint for each. A route matched by a regular expression is declared and counted under its regex source and marked as a regex. A handler joins to its method, with `blockingHandler` unwrapped. A router reachable through two parameterised mounts switches the module off with the kind `ROUTE_WALK_FAILED`. The route bridge reads OpenTelemetry's `/users/:id` as `/users/{id}`, so a request the module counted at a static path is not counted again.
- An endpoint can have a regex template, the regular expression a framework matches a route by, kept exactly as written and never merged with a path endpoint whose template reads the same. `EndpointLocation` gains `template_kind` on the wire, and the testkit's `EndpointRef` gains `isRegexTemplate`. `wasCalled`, `callCount` and `awaitEndpoint` address path endpoints only; `endpoints()` and `neverCalled()` list regex endpoints.
- Endpoint counting for Micronaut 4.0 to 5.x, as the module `micronaut`. It declares the URI routes Micronaut registers, including `RouteBuilder` routes and management endpoints, and counts a request once Micronaut matched it, before argument binding. The `HEAD` route Micronaut adds beside each `@Get` is not declared, and a `HEAD` request counts against the `GET` endpoint. WebSocket, `@Error` and status routes are not endpoints. `micronaut.server.context-path` stays in an annotated route's template. A handler joins to the method as its class file declares it, including an inherited method, a method of a controller with AOP advice and a Kotlin `suspend` function.
- Endpoint counting for Micronaut 3, as the module `micronaut-3`, on Netty and on micronaut-servlet. It declares and names routes as `micronaut` does and counts a request once the server handed on the route it matched, before the filters and the handler. A CORS preflight, a 404, a 405 and a status or `@Error` route count nothing. Micronaut 3 does not route a `default` method of an interface.
- Endpoint counting for Javalin, as the modules `javalin-6` (6.1 and later) and `javalin-7`. Each declares the HTTP routes Javalin registers, including `ApiBuilder` routes, `CrudHandler` routes and the OPTIONS routes of `HttpAllowedMethodsPlugin`, and counts a request once it reaches its handler, after the before-handlers. A `CrudHandler`'s five endpoints join to its methods. Javalin 6.0 reports `javalin-6` as disabled with the kind `LINKAGE_ERROR`.
- Endpoint counting for Spring WebFlux, as the module `spring-webflux`, on Spring Framework 5.3, 6 and 7. It declares annotated controllers, URL-mapped handlers, functional routes and `resources` routes, and counts a request once, with a CORS preflight as no call.
- A Spring functional route written in the Kotlin DSL (`router { }`, `coRouter { }`) names no handler, on Spring MVC and Spring WebFlux.
- `disabledEndpointModules` keeps single endpoint modules from installing, by name, separated by `;`.
- A module the configuration keeps off, by `disabledEndpointModules` or by `endpointsEnabled=false`, is reported as disabled with the kind `CONFIGURED_OFF`, in the wire format and in the testkit.
- Endpoint counting for micronaut-aws 3.x on Lambda, as part of `micronaut-3`, at the entry of `MicronautLambdaContainerHandler.handleRequest` from the route match the request carries.
- The Micronaut modules declare a router's routes only once a dispatch point they count at has been constructed: Netty's `RoutingInBoundHandler`, micronaut-servlet's `ServletHttpHandler`, micronaut-aws's `MicronautLambdaContainerHandler`, or `RouteExecutor` on Micronaut 4 and 5. A router that waits one flush interval with none constructed, or is still waiting at the final flush, reports the module as disabled with the new kind `ROUTES_NOT_COUNTED`, in the wire format and in the testkit, and the module declares nothing.

### Changed

- A JAX-RS resource class's routes are reported once the agent has seen the class defined or a route of it called. A resource class the JVM never defines reports no routes, and the agent logs a `WARNING` naming it (ADR 0028).
- Every chunk of a delta batch, manifest, static baseline and class listing closes at 8 MiB of encoded bytes or 90% of the collector's element limit for its kind, as well as at its entry cap. A class too large to send alone is reported as skipped in the manifest, and its hits are not sent. A static baseline that holds such a class is not sent at all, and the agent logs one WARNING that names the class.
- An `exportUrl` the agent cannot use turns the agent off for the JVM with one ERROR, in place of a warning and a fall back to `http://localhost:4319`. A URL with a user name or password is one of these. An `authToken` with a character outside the visible ASCII range `!` to `~` turns the agent off the same way. Neither ERROR quotes the token, or any of the URL but a host with an underscore.
- A service name, namespace, version, environment or instance ID over 1024 bytes is skipped with a warning, and the next source gives the value, since the collector refuses a payload that carries one.
- A Spring functional route that no walk declared counts a request under its method only when the method is `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS` or `TRACE`, and under `*` otherwise. A declared route keeps the method it was declared with.
- An endpoint module records at most 8,192 endpoints it finds only at dispatch, and past that logs one WARNING and records no new ones. It also binds at most 8,192 request keys at dispatch; past that a request still counts, and its endpoint is resolved again each time. Declared endpoints are never limited.
- The reason of a disabled endpoint module names the exception's class, not its message, unless the exception is a linkage error.
- The shutdown flush ends with one empty delta batch that carries `final_flush`, sent after its other batches and stamped with the pending state they left. No other batch carries it, so a run whose last hit batch was refused or lost no longer reads as having ended cleanly with nothing pending.
- The static baseline keeps only the copy of a class name the JVM loads, the first in the classpath's search order, and searches the jars a manifest `Class-Path` names right after the jar that names them. A shadowed copy no longer makes a loaded class read as never loaded.

### Fixed

- A CORS preflight whose `Origin` holds a character Spring Security's firewall refuses no longer disables the Spring WebFlux or Spring MVC module.

- With OpenTelemetry's Spring MVC instrumentation present, a request that a filter answered before `DispatcherServlet` ran, a 401 from Spring Security for one, is no longer counted against the route OpenTelemetry looks up afterwards. Annotated, functional and `resources(...)` routes count only a lookup made by the dispatch.

- With the route bridge on, a servlet's extension mapping (`*.do`) and default mapping (`/`) count once, under the `servlet` module, instead of also under the bridge's `/*.do`, `/*` and `/`.
- With the route bridge on, a route a root-context application serves is no longer attributed to another application's route when a second application's context path makes the two read alike. Both count, the second as the bridge's duplicate.

- With OpenTelemetry's agent listed before this one, no endpoint module is switched off and no class goes unwoven. The JAX-RS module reads the interfaces OpenTelemetry generates for a framework class, and any other class defined without a class file, from the loaded class, and decides that a class whose supertype cannot be loaded at all can never be defined, so it is no match and the module stays on. A module whose type matcher cannot decide about a class switches only itself off, with the kind for a transform failure, instead of aborting the weave of every module that matched the class.
